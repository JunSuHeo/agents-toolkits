# testing-verification

변경의 완료 조건을 실제 명령과 결과로 확인한다.

## 입력과 선행 조건

- 변경 파일, 지원 환경, 테스트 요구와 인수 조건
- 프로젝트에서 승인한 테스트 명령과 검증용 데이터가 준비되어 있다.

## 적용 범위와 도구

승인된 로컬 빌드, 정적 분석, 테스트를 실행하고 결과를 TESTING 기록에 남긴다.

## 절차

1. 변경과 연결된 필수·선택·적용 불가 Gate를 결정한다.
2. 빠른 검증부터 실행한 뒤 필요한 통합 경로를 검증한다.
3. 환경, 명령, 종료 코드, 기대와 관찰, 실패 및 미검증 범위를 기록한다.

## 결과 기록 예시 — 월 경계 수정

아래 값은 기록 형식을 보여주는 합성 예시다. 실제 보고에는 실행 환경과 실행한 명령을 적는다.

| 검증 | 실행과 결과 | 관찰 |
| --- | --- | --- |
| 날짜 경계 회귀 | `pytest -q tests/test_month_end.py`, 수정 전 1, 수정 후 0 | 수정 후 31일 정오 행 포함, 다음 달 1일 0시 행 제외 |
| CSV 사용자 경로 | 로컬 CLI에서 합성 거래 두 건 내보내기, 종료 0 | 파일을 열어 헤더와 대상 거래 한 건 확인 |
| 운영 DB 시간대 | 실행 환경 미확보 | 실제 DB 변환 경계는 미검증 |

명령이 성공해도 산출물이 요구와 다르면 해당 인수 기준은 실패다. 필수 경로를 확인할 수 없을 때는 대신 실행한 검사와 아직 필요한 환경을 함께 남긴다.

## 출력과 검증

TESTING 기록 및 실제 통과·실패 판단. 필수 실패 및 건너뛴 항목을 통과로 분류하지 않는다.

## 실패 처리와 제한

환경 장애와 제품 결함을 근거로 구분하고 안전한 재현 조건을 기록한다. 프로젝트의 보안 및 승인 정책을 따른다. 선행 Skill 의존성은 없다.
