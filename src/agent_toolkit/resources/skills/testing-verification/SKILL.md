# testing-verification

변경의 완료 조건을 실제 명령과 결과로 확인한다.

## 입력과 선행 조건

- 변경 파일, 지원 환경, 테스트 요구와 인수 조건
- 프로젝트에서 승인한 테스트 명령과 검증용 데이터가 준비되어 있다.

## 적용 범위와 도구

할당된 프로젝트와 명시적으로 허용된 범위에서만 적용한다. 사용 도구는 로컬 빌드, 정적 분석, 테스트와 TESTING 기록다.

## 절차

1. 변경과 연결된 필수·선택·적용 불가 Gate를 결정한다.
2. 빠른 검증부터 실행한 뒤 필요한 통합 경로를 검증한다.
3. 환경, 명령, 종료 코드, 기대와 관찰, 실패 및 미검증 범위를 기록한다.

## 출력과 검증

TESTING 기록 및 실제 통과·실패 판단. 필수 실패 및 건너뛴 항목을 통과로 분류하지 않는다.

## 실패 처리와 제한

환경 장애와 제품 결함을 근거로 구분하고 안전한 재현 조건을 기록한다. 프로젝트의 보안 및 승인 정책을 따른다. 선행 Skill 의존성은 없다.
