# task-decomposition

중간 이상 작업을 의존성과 검증 진입점이 있는 단위로 나눈다.

## 입력과 선행 조건

- 요구사항, 인수 조건, 모듈 경계
- 범위와 기준 커밋을 확인한다.

## 적용 범위와 도구

할당된 프로젝트와 명시적으로 허용된 범위에서만 적용한다. 사용 도구는 읽기, 검색, Git 조회다.

## 절차

1. 사용자에게 보이는 결과부터 역산하여 설계, 구현, 검증 작업을 정한다.
2. 단위마다 입력, 출력, 변경 경로, 의존성과 검증 명령을 지정한다.
3. 겹치는 쓰기 경로를 순차화하고 독립 작업만 병렬 후보로 남긴다.

## 분해 예시 — 거래 CSV 내보내기

| 작업 | 소유 경로와 입력 | 완료 조건 | 선행 작업 |
| --- | --- | --- | --- |
| A. 출력 계약 확정 | 거래 열 정의와 샘플 | 열 순서, 시간대, 빈 결과를 샘플 한 건으로 확인 | 없음 |
| B. 파일 생성 | 서버 내보내기 모듈 | 샘플과 실제 CSV의 헤더·행이 일치 | A |
| C. 다운로드 버튼 | 화면과 UI 테스트 | 샘플 응답으로 파일명과 실패 안내를 확인 | A |
| D. 통합 검증 | 사용자 다운로드 경로 | 화면에서 받은 파일이 A의 계약과 일치 | B, C |

B와 C는 소유 경로가 분리돼 병렬 후보가 된다. 양쪽이 공통 타입을 고쳐야 하면 타입 수정은 A에 모은다. 작업 하나로 끝낼 수 있는 변경은 이 표를 만들기 위해 쪼갤 필요가 없다.

## 출력과 검증

작업 ID, 소유 역할, 경로, 의존성, 검증 및 통합 순서. 작업 사이에 순환 의존성이 없으며 각 완료 조건에 담당자가 있다.

## 실패 처리와 제한

독립 경계가 불명확하면 하나의 작업으로 묶고 별도 검토를 배정한다. 프로젝트의 보안 및 승인 정책을 따른다. 선행 Skill 의존성은 없다.
