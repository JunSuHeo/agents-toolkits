# 소비자 기준의 계약 검토

사용 중인 버전과 지원 기간, 제공자와 소비자 배포 순서를 확인한다. 요청 필드·반환 형태·오류·기본값 중 변경되는 부분과 실제 소비자가 해석하는 방법을 찾는다.

1. 지원 대상인 구버전 호출자의 요청이나 직렬화 샘플을 확보한다. 새 제공자에 같은 입력을 넣고 기존 소비 방식으로 결과를 읽는다.
2. 독립 배포라면 신버전 소비자가 구버전 제공자를 만나는 기간도 확인한다. 추가 필드를 거부하는 디코더, 열거형의 미지 값, 누락과 null의 차이를 변경 내용에 맞게 검토한다.
3. 깨지는 조합이 있으면 추가 필드의 기본값, 전환용 어댑터, 버전 분리 중 실제 배포 순서에 맞는 방법을 고른다. 제거 가능한 시점은 소비자 전환 근거와 연결한다.

## 예시 — 필수 입력 추가

기존 요청 `{"name":"샘플"}`에 새 제공자가 필수 `locale`을 요구하면 구버전 호출이 실패한다. 기존 기본 언어를 계약에서 확인한 뒤 필드 생략 시 같은 결과가 나오는지 검사한다. 새 호출의 명시적 언어와 잘못된 언어의 오류도 확인한다. 출력으로 버전 조합, 샘플 입력, 기대·관찰, 배포 순서 제약을 남긴다.
