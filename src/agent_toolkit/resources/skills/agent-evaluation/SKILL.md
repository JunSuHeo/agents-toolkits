# 에이전트 변경 평가

변경 목적을 관찰 가능한 행동으로 표현한다. 정답 텍스트가 여러 개인 과제는 필수 사실, 허용된 도구 호출, 사용자에게 전달할 결과 등 각각 확인할 수 있는 기준으로 나눈다.

1. 정상 요청, 근거가 부족한 요청, 도구가 실패하는 요청 중 변경과 관련 있는 사례를 준비한다. 기대 결과와 실패 판정을 실행 전에 기록한다.
2. 합성 입력과 고정된 도구 응답으로 기준 버전과 후보를 비교한다. 모델 버전, 설정, 반복 횟수를 남긴다. 외부 호출과 비용은 승인된 범위에서만 사용한다.
3. 최종 답변과 호출 기록을 함께 판정한다. 총점이 올라도 필수 기준에서 새로 실패한 사례는 별도로 표시한다. 대역만 사용한 결과에는 실제 모델에서 확인할 항목을 남긴다.

## 예시 — 조회 요청 처리

“주문의 배송일을 알려줘”에 배송일이 있는 경우, 주문을 찾지 못한 경우, 조회 도구가 실패한 경우를 둔다. 첫 사례는 반환된 날짜와 일치해야 하고, 나머지 두 사례는 날짜를 추정하지 않아야 한다. 세 사례 모두 읽기 도구만 호출했는지 기록한다. 평가표에는 사례별 기준·후보 결과와 달라진 호출을 남긴다.
