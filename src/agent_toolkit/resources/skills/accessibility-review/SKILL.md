# 사용자 흐름의 접근성 검토

검토할 과업과 시작·종료 상태를 정한다. 역할 트리나 마크업에서 예상 동작을 찾은 뒤 실제 제공 환경에서 같은 과업을 수행한다.

1. 키보드나 플랫폼의 탐색 방식으로 진입, 선택, 제출, 취소를 시도한다. 초점 순서, 현재 위치 표시, 닫은 뒤 돌아갈 곳을 관찰한다.
2. 시각적 레이블과 접근 가능한 이름을 비교한다. 오류·로딩·완료 상태가 보조 기술 사용자에게 전달되는지 확인한다. 도구가 없으면 확인한 속성과 남은 실기기 검증을 구분한다.
3. 실패를 “어떤 사용자가 어느 동작에서 멈추는가”로 적고 과업을 처음부터 다시 수행해 수정 결과를 확인한다.

## 예시 — 이름 변경 대화상자

버튼으로 열면 입력란으로 초점이 이동하고, 빈 값 제출 시 오류가 해당 필드에 연결되어야 한다. 취소하면 목록에서 같은 행의 버튼으로 돌아가는지 확인한다. 기록에 열기·오류·닫기의 실제 초점 위치를 남기면 후속 작업자가 같은 순서로 재검증할 수 있다.
