# agent-improvement

반복되는 작업 실패를 비식별 근거로 정리해 Toolkit 개선안을 작성한다.

## 입력과 선행 조건

- 반복 사례, 영향, 관련 규칙 및 이전 검증
- 공통 개선 대상인지 확인하고 프로젝트 전용 정보와 민감 데이터를 제거한다.

## 적용 범위와 도구

할당된 프로젝트와 명시적으로 허용된 범위에서만 적용한다. 사용 도구는 읽기, 검토, 합성 자료 기반 검증다.

## 절차

1. 반복 원인과 적용할 수 있는 프로젝트 범위를 설명한다.
2. 작은 규칙 또는 Skill 변경안을 제안하고 기존 정책 및 Adapter와의 충돌을 확인한다.
3. 회귀 검증과 이관 계획을 작성하고 사용자 승인 단계를 남긴다.

## 출력과 검증

비식별 개선 제안, 회귀 근거, 호환성 및 승인 요청. 보안·핵심 정책은 별도 사용자 승인이 있고, 사례는 공개 가능한 입력으로 재현된다.

## 실패 처리와 제한

근거가 한 프로젝트에만 속하면 그 프로젝트 규칙으로 기록한다. 프로젝트의 보안 및 승인 정책을 따른다. 선행 Skill 의존성은 없다.
