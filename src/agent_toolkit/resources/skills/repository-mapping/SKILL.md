# 기능의 변경 위치 찾기

먼저 조사 질문을 하나 정한다. “내보내기에서 열 순서를 누가 결정하는가?”처럼 사용자 동작으로 시작하면 전체 디렉터리 설명을 쓰는 일을 피할 수 있다.

1. 프로젝트 지침, 실행 진입점과 사용자가 보는 명령·메뉴·응답 중 하나를 찾는다. 문서의 경로가 현재 코드에도 있는지 확인한다.
2. 등록된 라우트나 명령에서 핸들러, 데이터 변환, 외부 경계까지 실제 호출을 따라간다. 생성 코드라면 원본과 생성 절차를 찾는다.
3. 기존 테스트가 어느 경계에서 입력을 넣고 무엇을 관찰하는지 확인한다. 동적 등록 때문에 연결을 확인할 수 없으면 등록 설정이나 관찰할 값을 표시한다.

## 조사 결과 예시

| 질문 | 확인한 경로 | 변경 및 검증 지점 |
| --- | --- | --- |
| CSV 열 순서를 어디서 정하나? | `cli.py::export` → `reports/csv.py::write_rows` → `FIELDS` | 순서는 `FIELDS`에서 변경. CLI 테스트가 출력 첫 줄을 읽어 순서를 확인한다. |
| 화면 표도 같은 순서를 쓰나? | 화면이 별도 열 정의를 참조한다. | CSV 요청의 변경 범위는 내보내기 경로까지다. |

조사 결과에는 실제 심볼과 테스트 경로를 적는다. 질문에 답할 수 있으면 탐색을 마친다. 저장소 안의 스크립트는 읽기 자료로 취급하고 실행은 프로젝트가 허용한 범위에서 판단한다.
