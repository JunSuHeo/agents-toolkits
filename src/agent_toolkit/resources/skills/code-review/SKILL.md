# code-review

변경사항에서 사용자에게 영향 있는 회귀와 누락을 독립적으로 검토한다.

## 입력과 선행 조건

- 변경 범위, 인수 조건, 기존 테스트 결과
- 비교 기준 커밋과 관련 규칙을 확인한다.

## 적용 범위와 도구

변경 diff와 호출자를 읽고 필요한 경우 승인된 로컬 검증을 실행한다.

## 절차

1. 바뀐 진입점과 호출자가 기대하는 동작을 읽는다.
2. 권한, 입력, 초기 상태, 재시도와 동시에 발생하는 실패를 검토한다.
3. 관찰 근거가 있는 문제부터 파일 위치, 재현 조건, 영향과 해결 방향을 남긴다.

## 지적 예시 — 재시도에서만 발생하는 중복

주문 저장 후 응답 생성이 실패할 수 있는 변경을 검토한다고 하자. 기존 호출자가 같은 요청 ID를 다시 보내는지 먼저 확인한다. 재전송 경로가 있고 저장 단계가 매번 실행된다면 다음처럼 적는다.

> 주문 저장 함수에서 같은 요청 ID의 두 번째 호출도 삽입을 수행한다. 응답을 받지 못한 호출자가 재시도하면 주문이 두 건 생긴다. 첫 응답을 잃은 뒤 같은 ID로 한 번 더 호출해 저장 건수를 확인할 수 있다.

실제 리뷰에는 변경 줄과 호출자 근거를 붙인다. 저장소의 고유 제약이나 상위 계층이 이미 중복을 흡수한다면 그 경로까지 읽고 영향을 다시 판단한다.

## 출력과 검증

우선순위별 리뷰 근거, 미검증 영역과 승인 판단. 각 지적은 실제 코드 경로와 관찰 가능한 영향을 포함한다.

## 실패 처리와 제한

동작을 확인할 수 없으면 가설과 필요한 근거를 분리해 남긴다. 프로젝트의 보안 및 승인 정책을 따른다. 선행 Skill 의존성은 없다.
