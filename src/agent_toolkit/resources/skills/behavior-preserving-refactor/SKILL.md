# 동작을 보존하는 리팩터링

공개 진입점과 대표 호출자를 찾고 보존할 반환값, 오류 종류, 출력 순서, 저장 시점을 적는다. 기존 데이터나 여러 호출자가 있을 때는 현재의 차이도 계약 후보로 본다.

1. 변경 전 정상·경계 입력으로 기준 동작을 수집한다. 기존 테스트에 빈틈이 있고 회귀 가능성이 있으면 해당 경계에 테스트를 추가한다.
2. 옮기기, 이름 변경, 공통 로직 추출을 검토 가능한 단위로 진행한다. 상태를 공유하거나 실행 순서를 바꾸는 단계에서 관찰값을 다시 비교한다.
3. 차이가 나오면 계약 근거와 대조한다. 별도 제품 결정이 필요한 동작 변경은 기록하고 요청한 구조 변경 범위를 유지한다.

## 예시 — 중복된 금액 변환기

주문 가져오기는 빈 금액을 누락 값으로 보존하고, 견적 입력은 빈 금액을 오류로 처리한다고 하자. 공통화할 부분은 숫자 형식 변환이다. 빈 값 정책은 각각의 호출자에 두고, 두 공개 진입점에 빈 값과 소수 금액을 다시 넣는다. 전후 결과표에 반환값뿐 아니라 저장된 레코드 유무도 기록한다.
