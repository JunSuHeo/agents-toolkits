# ci-debugging

GitHub Actions 실패를 로그와 워크플로 정의에서 찾아 로컬 검증을 설계한다.

## 입력과 선행 조건

- 실패한 작업·스텝, 해당 커밋, 비밀이 제거된 로그와 workflow 파일
- 워크플로 읽기 권한과 안전한 테스트 환경을 확인한다.

## 적용 범위와 도구

할당된 프로젝트와 명시적으로 허용된 범위에서만 적용한다. 사용 도구는 읽기, Git 조회, 승인된 로컬 검증다.

## 절차

1. 첫 실패 명령과 종료 코드를 찾고 후속 연쇄 실패를 구분한다.
2. 해당 커밋의 runner, matrix, 파일 경로, 잠금 및 권한을 대조한다.
3. 최소 로컬 재현 뒤 수정 제안을 검증한다. CI 재실행은 승인 범위를 따른다.

## 출력과 검증

첫 실패 원인, 근거, 변경안과 추가 검증. 첫 실패 단계를 다시 확인하고 의도치 않은 권한 확대가 없는지 확인한다.

## 실패 처리와 제한

로그 접근 불가 시 필요한 작업 ID와 로그 범위만 요청한다. 프로젝트의 보안 및 승인 정책을 따른다. 선행 Skill 의존성은 없다.
