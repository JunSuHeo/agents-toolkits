# 제품 결함 진단

사용자가 밟은 진입점, 입력, 기대 결과, 관찰 결과, 마지막 정상 조건을 모은다. 로그에 찍힌 마지막 예외가 최초 오류인지 확인한다.

1. 임시 데이터로 원래 경로를 재현하고 닮은 정상 입력을 하나 둔다. 간헐적이면 시각·순서·반복 횟수를 기록한다.
2. 가능한 원인마다 서로 다른 예측을 세운다. 다음 관찰은 두 예측을 가를 수 있는 경계에서 한다. 한 번에 바꾸는 조건을 줄인다.
3. 원인이 확인되면 결함을 드러낸 입력을 회귀 사례로 남긴다. 수정 전후에 같은 진입점에서 실패 사례와 정상 대조군을 모두 확인한다.

## 예시 — 월말 행 누락

3월 보고서에서 31일 오후 거래만 빠진다. 원본 조회 직후 이미 행이 빠지면 조회 범위를, 조회에 포함됐다가 CSV에서 빠지면 변환기를 살핀다. 같은 시간대의 31일 00시, 31일 정오, 4월 1일 00시 행을 넣어 끝 경계의 포함 여부를 확인한다.

기록에는 재현 조건, 최초 불일치, 배제한 설명과 근거, 수정 후 관찰을 남긴다. 재현이 안 되면 관찰한 횟수와 다음에 확보해야 할 최소 입력을 적는다.
