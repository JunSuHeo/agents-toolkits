# security-audit

인가·비밀·외부 입력·의존성 변경을 방어적으로 검토한다.

## 입력과 선행 조건

- 범위, 데이터 분류, 변경, 권한 모델과 의존성 고정 파일
- 읽기 범위와 안전한 로컬 검증 범위를 확인한다.

## 적용 범위와 도구

할당된 프로젝트와 명시적으로 허용된 범위에서만 적용한다. 사용 도구는 읽기, 검색, 승인한 정적 분석 도구다.

## 절차

1. 외부 입력, 권한 경계와 민감 데이터의 이동 경로를 식별한다.
2. 권한 기본값, 비밀 저장·로그, 구성 상속과 의존성 출처를 검토한다.
3. 관찰한 노출 경로와 완화 방안을 남기고 다룬 경계를 검증 목록에 기록한다.

## 검토 예시 — 내보내기 작업의 데이터 범위

화면에서 조직을 선택한 후 백그라운드 작업이 보고서를 만드는 경우, 요청 시점의 멤버십 검사와 작업자가 조회에 사용하는 조직 식별자를 따라간다. 권한이 바뀌었을 때 어떤 시점의 권한을 적용할지는 프로젝트 정책에서 확인한다.

검토 기록에 요청 처리기, 작업 메시지의 필드 이름, 조회 함수, 권한을 확인한 위치를 연결한다. 정상 범위 검증에는 합성 조직의 자료를 사용한다. 로그나 오류 메시지를 인용할 때는 토큰과 레코드 원문을 생략한다.

## 출력과 검증

방어적 발견 사항, 영향 범위, 완화책, 우선순위. 민감 값 원문을 공유하지 않고 필요한 독립 검증과 승인 여부를 확인한다.

## 실패 처리와 제한

고위험 문제가 확인되면 작업 경계를 유지하고 담당자에게 알린다. 프로젝트의 보안 및 승인 정책을 따른다. 선행 Skill 의존성은 없다.
