# 성능 회귀 조사

먼저 사용자가 기다리는 구간과 기준 지표를 정한다. 응답 지연, 최대 메모리, 처리량 중 요청과 연결된 값을 고르고 기존 예산이나 비교 버전을 기록한다.

1. 대표 입력 크기, 데이터 분포, 동시성, 빌드 모드, 캐시 상태를 고정한다. 초기 실행 비용이 문제면 최초 실행을 따로 측정한다.
2. 여러 번 측정하여 편차를 남긴다. 지연이 큰 구간에서 호출 수, 읽은 행 수, 할당량 등 원인을 구분할 수 있는 관찰값을 수집한다.
3. 한 번에 한 가설을 검증한다. 같은 조건에서 결과의 정확성과 비용을 다시 측정한다. 개선 폭이 실행 간 편차에 묻히면 판단을 유보한다.

## 예시 — 목록이 길 때만 느린 조회

합성 자료로 10행과 100행을 조회할 때 쿼리가 11회와 101회라면 행별 추가 조회를 의심할 근거가 된다. 묶음 조회를 적용한 후보에서 반환 순서와 누락 여부를 비교하고, 쿼리 수와 전체 요청 시간을 함께 기록한다. 로컬 수치는 해당 데이터와 환경의 결과로 표시한다.
