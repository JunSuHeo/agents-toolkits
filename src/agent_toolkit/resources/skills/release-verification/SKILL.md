# 릴리스 후보 검증

검증할 버전과 산출물, 지원 환경, 이전 버전을 정한다. 사용자 문서에 나온 설치·실행 경로를 선택하고 개발 체크아웃과 분리된 임시 환경을 사용한다.

1. 후보 산출물을 설치한 뒤 실제로 로딩된 버전과 경로를 확인한다. 패키징 누락을 볼 수 있도록 내장 자료를 읽는 대표 기능을 실행한다.
2. 기존 사용자를 지원하면 이전 버전으로 샘플 상태를 만든 뒤 후보로 업그레이드한다. 사용자 파일 보존, 저장 형식 호환성, 다시 실행했을 때의 상태를 확인한다.
3. 산출물 식별자와 환경별 실행 결과, 미검증 대상, 진행을 막는 실패를 기록한다. 게시와 배포는 해당 대상에 대한 승인 범위를 따른다.

## 예시 — CLI는 열리지만 템플릿이 없는 wheel

빈 디렉터리에서 설치된 CLI의 버전을 확인한 후 템플릿 하나를 생성하고 내용을 읽는다. 도움말이 열려도 생성 과정에서 파일을 찾지 못하면 패키징 실패다. 수정한 wheel로 같은 설치 과정을 새 환경에서 반복하고 확인에 사용한 파일명을 남긴다.
