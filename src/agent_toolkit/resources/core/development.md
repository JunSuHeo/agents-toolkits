# 개발 원칙

요구사항, 완료 기준, 제약과 기존 작업 방식을 확인한다. 공통 표준은 프로젝트의 제품 요구사항과 분리한다. 제한된 범위의 변경에는 기존 설계와 진입점을 유지하고 필요한 경계에서만 새로운 추상화를 도입한다.

변경 전후에 동일한 정상 진입점을 사용해 동작을 비교한다. 오류, 이전 데이터, 재시도 및 동시성은 실제로 영향이 있는 경우에 확인한다. 언어와 프로젝트가 이미 채택한 포맷과 테스트 도구를 따른다.

문서에는 현재 명령, 책임, 결정과 확인된 사실을 기록한다. 기존 호출자에 영향이 있을 때 인터페이스와 이전 방법을 설명한다.
