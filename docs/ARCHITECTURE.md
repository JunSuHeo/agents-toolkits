# 아키텍처

`CLI → YAML/Pydantic → catalog.resolve → render → plan → apply` 순서로 실행한다. 구성과 카탈로그 검증 및 렌더까지는 프로젝트에 쓰지 않는다. 상태, 차이와 업데이트 미리보기는 같은 계획 로직을 공유한다. 설치 검증은 현재 생성물을 Lock의 체크섬과 비교한다.

- `models.py`는 스키마와 YAML/JSON 입력을 검증한다.
- `catalog.py`는 배포 리소스를 읽고 스택 및 Skill 의존성, 프로필·구성 기본값, 필수 Gate를 결정한다.
- `render.py`는 Markdown 파일을 조합한다. `adapters.py`는 등록된 도구의 Skills 경로와 역할 직렬화만 담당한다. 파일 생성을 수행하는 Adapter나 모델 클라이언트는 없다.
- `project.py`는 상태, 잠금, 체크섬과 충돌 규칙을 담당한다. `files.py`가 허용 경로 경계 검사와 변경 트랜잭션을 맡는다.
- `git_ops.py`는 Git 조회와 Toolkit worktree 생명주기를 담당한다. `checks.py`는 명시적으로 선택한 로컬 검증 명령을 실행한다.

## 규칙과 소유권

공통 규칙 → Profile → Stack → 프로젝트 규칙 → 작업 지침 순서로 구체화한다. 필수 보안 규칙과 승인 범위는 항상 적용한다. 같은 권한·접근 규칙이 충돌하면 사용자에게 알린다. 프로그램은 관리 경로와 필수 Gate 분류를 강제하고, 사람과 네이티브 도구가 역할 파일 범위·네트워크·배포 승인을 집행한다.

- `agent-toolkit.yml`은 사용자 소유 구성이다. 설치 시 새 파일만 만들며 이후 버전은 lock에서 관리한다.
- `toolkit.lock`은 생성물의 소유권과 SHA-256 기준을 기록한다. 잠금 자체를 신뢰하는 입력으로 처리하되, 지정할 수 있는 경로는 생성 가능한 이름으로 제한한다. 인증 서명을 제공하지 않는다.
- 기존 `AGENTS.md` 및 `CLAUDE.md`는 보존한다. 신규 진입점에는 공통 가이드를 연결하고, 기존 진입점에는 사용자가 연결을 추가한다.
- `.agent-toolkit/GUIDE.md`, 등록한 Skills 및 역할, 선택한 워크플로는 관리 대상이다. `.agent-toolkit/project-rules.md`, 작업별 인수인계와 애플리케이션 문서는 사용자가 관리한다.
- Windows reparse point를 포함한 심볼릭 링크, 특수 파일, 하드링크, 대소문자 충돌은 쓰기 경로에서 차단한다.

## 업데이트

대상 버전은 현재 실행 중인 Toolkit이다. lock을 기준으로 변경된 생성물은 충돌로 분류하고, 새 파일 이름에 미관리 파일이 있으면 충돌로 분류한다. 변경 계획을 다시 검증하고 프로젝트별 배타 잠금 아래 보관본을 만든 후 원자적 파일 교체와 적용 후 읽기 검증을 수행한다. lock은 마지막에 교체한다. 일반적인 예외는 보관본으로 롤백한다. 프로세스 강제 종료 후 복구와 동시 편집 제한은 README에 따른다.
